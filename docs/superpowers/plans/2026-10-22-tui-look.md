# TUI look Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One palette, one pane style and one key bar across every desktop screen, and a dashboard
where an issue or a host opens into a detail screen with live output.

**Architecture:** A new package `installer/internal/ui/theme` holds the palette, glyphs, the pane,
the key bar, toasts, the margin and the too-small screen. The dashboard (`internal/dash`), the
full-screen and inline renderers (`internal/ui`) draw only through it. The host gains `flocc peek`
and `flocc logs --issue`; the desktop reaches them, and `doctor --json`, through one new
`ship.Source.Run` call.

**Tech Stack:** Go 1.27, bubbletea/v2 v2.0.2, bubbles/v2 v2.0.0 (key, help, spinner, viewport),
lipgloss/v2 v2.0.6, huh/v2 v2.0.3, `github.com/charmbracelet/x/ansi` (already in `go.sum`, becomes
direct). Python 3 host CLI under `src/flocc`, pytest.

**Spec:** `docs/superpowers/specs/2026-10-22-tui-look-design.md`, building on
`docs/superpowers/specs/2026-10-22-cli-tui-design.md`. Read both.

## Global Constraints

- Layout: panes fill the terminal less a margin of 1 row top and bottom and 2 columns each side.
- Six semantic colours (accent, up, down, warn, err, dim), dark and light; stoat's hex values; each
  light colour at least 4.5:1 against `#FFFFFF`.
- Full-screen programs send `tea.RequestBackgroundColor` in `Init` and redraw on
  `tea.BackgroundColorMsg`; dark until it arrives. Inline sends it once, in `Init`.
- Pane: rounded border in accent, padding 0×1, optional bold title set into the top border, optional
  right-aligned dim hint in the top border.
- Glyphs: `❯` selection, `●` up, `○` down, `✗` failed, `✓` done, MiniDot spinner (`⠋` first frame)
  for running work, `·` separator.
- Key bar from `key.Binding` values with bubbles `help`; a key that does nothing on the current row
  is dimmed (still listed) and does nothing when pressed; `?` shows every key; the bar wraps, never
  truncates.
- Below 60×20 a screen says the terminal is too small and how big it is (`terminal too small:
  59×19 · needs 60×20`). Side-by-side panes stack below 100 columns.
- Action errors are a toast at the top right for 4 s, with a generation. Prompts and confirmations
  use a fixed status line above the key bar (`release NF-240? y/N`).
- Plain output is byte-for-byte unchanged; the event stream is unchanged.
- Host strings are sanitised as today (`saved.Sanitize` per line); no secret reaches a frame, a log
  or an event.
- Charm pins stay; no new module. `tea.ExecProcess` fills only the child's unset streams;
  `tea.Println` prints nothing on the alt screen; programs use `tea.WithoutSignalHandler()`.
- Go builds and tests: `export GOTMPDIR=~/.cache/go-tmp` (create it); `/tmp` is nearly full.
- Commits: `git commit -s`, no Co-Authored-By, no AI attribution. Comments carry only facts the
  code cannot show, at the density of the file around them. Grep before writing any helper.
- Frame tests compare text with escapes stripped at 59×19, 80×24 and 140×40, against golden files
  under the package's `testdata/`, regenerated with `go test ./internal/<pkg> -run Golden -update`.
- Never touch a live host; never run `flocc setup`, `keys` or `ship` for real.
- `ui.modalBox`, `ui.Form`, `ui.overlay` and `ui.advance` keep their signatures in stream B:
  stream A's branch still has `ui/confirm.go` calling them until A deletes it. B adds new helpers
  beside them instead of changing them.
- Dashboard key order: an open status-line question takes the key first, then filter or search
  typing, then the screen's own keys. So `q` typed into the filter is text, not quit.
- Tests that assert colours build their model with `theme.New(true)`, not `FromEnv`: under
  `NO_COLOR` or `TERM=dumb` a `FromEnv` theme is Plain and such a test would pass without
  checking anything.

## Review Focus

1. A host string carrying escape sequences or 300 characters (a claim title, a log line, a doctor
   detail, a host name) draws sanitised and no frame line passes the terminal width. Test in Task 4
   and Task 5.
2. A resize while a detail screen or the pager is open (140×40 → 80×24 → 59×19 → 140×40) redraws
   the same screen at each size without panicking. Test in Task 5.
3. The open issue drops out of the next poll (released elsewhere): the issue screen says it is no
   longer claimed, its `a` and `r` dim, and nothing indexes past the rows. Test in Task 5.
4. Leaving an issue screen and opening another while the first one's peek is still out: the late
   answer never shows on the second screen. Test in Task 5.
5. Empty data: no hosts, a host with no claims, a filter with no match, titles unavailable. Each
   shows its own sentence from the spec. Test in Task 4.

func lum(hex string) float64 {
	ch := func(i int) float64 {
		v, _ := strconv.ParseUint(hex[i:i+2], 16, 8)
		c := float64(v) / 255
		if c <= 0.03928 {
			return c / 12.92
		}
		return math.Pow((c+0.055)/1.055, 2.4)
	}
	return 0.2126*ch(1) + 0.7152*ch(3) + 0.0722*ch(5)
}
